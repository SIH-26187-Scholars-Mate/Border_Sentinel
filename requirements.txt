# Border Sentinel — one combined environment for backend/ + ai/.
#
# Both used to have their own venv + requirements.txt. They're merged here
# because they're really one Python process tree: the backend spawns the AI
# module as a child process (see backend/app/services/camera_worker.py), so
# there's no real benefit to keeping them isolated — and the old split had
# an actual version conflict (ai/requirements.txt capped pytest<9, backend's
# pinned pytest==9.1.1). One venv, one install, no conflict.
#
# Set up once from the project root:
#   python -m venv .venv
#   source .venv/bin/activate        # .venv\Scripts\activate on Windows
#   pip install -r requirements.txt
#
# backend/requirements.txt and ai/requirements.txt now just point here
# (`-r ../requirements.txt`) so any old `pip install -r backend/requirements.txt`
# muscle memory still works and installs the same combined set.

# ── AI module (OpenCV/YOLO/OCR) — everything backend doesn't already pull in.
# fastapi/uvicorn/httpx/pydantic-settings/python-multipart/pytest are omitted
# here on purpose: the AI module only ever needed loose ranges for them
# (e.g. fastapi>=0.115,<1), and the pinned backend versions above already
# satisfy every one of those ranges — no need to list them twice.
#
# torch is listed explicitly (and BEFORE ultralytics) so pip installs the
# CPU-only build from PyTorch's own wheel index instead of the default
# CUDA build from PyPI. The default build drags in ~10 separate
# nvidia-*-cu12 packages (cuBLAS, cuDNN, cuFFT, etc.) — several GB of CUDA
# runtime libraries meant for GPU inference, which is why requirements.txt
# suddenly ballooned. The extra-index-url below only supplies torch/
# torchvision; every other package above still resolves from normal PyPI.
# If you DO have an NVIDIA GPU and want GPU-accelerated inference, delete
# these two lines and let ultralytics pull the default CUDA build instead.
